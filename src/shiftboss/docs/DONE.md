# 完成标准

一件活做到什么程度算完。共五列：原型、成形、堆叠、收敛、维护。

## 1. 查哪一列

1. 列名就是任务书 `meta.json` 里 `完成标准` 的值。
2. 这次改动碰到项目文档（见 `AGENTS.md`）「完成标准」一节的「不放松清单」里的事时，碰到的那部分查「维护」列。
3. 其余全部查 `meta.json` 写的那一列；不看别的列。
4. 用户宣布项目改用哪一列；派活方按项目说明「完成标准」给每份任务书写列名。

## 2. 执行方：段内做什么

「必须」：交回前做完。「是」：可以做。「否」：不做。

| 动作 | 原型 | 成形 | 堆叠 | 收敛 | 维护 |
| --- | --- | --- | --- | --- | --- |
| 对改过的 `.js`、`.mjs`、`.py` 文件做语法检查 | 必须 | 必须 | 必须 | 必须 | 必须 |
| 改了界面：打开页面亲眼看改动处 | 必须 | 必须 | 必须 | 必须 | 必须 |
| 运行合同判据写出名字的现成命令 | 必须 | 必须 | 必须 | 必须 | 必须 |
| 开发中临时写脚本查问题，用完不提交 | 是 | 是 | 是 | 是 | 是 |
| 为证明判据做到而新写检查脚本、浏览器探针 | 否 | 是 | 是 | 是 | 是 |
| 跑改动涉及那一层的现有测试 | 否 | 否 | 否 | 必须 | 必须 |
| 新增常驻测试（进项目测试目录或登记进生成计划） | 否 | 只为不放松清单 | 只为不放松清单 | 是 | 是 |
| 跑全量测试、全量页面合同、生成、ROM 构建、打包 | 否 | 否 | 否 | 否 | 否 |
| 把检查脚本、探针输出、截图提交进仓库 | 否 | 否 | 否 | 只提交常驻测试 | 只提交常驻测试 |
| 检查失败后不改任何东西原样再跑 | 否 | 否 | 否 | 否 | 否 |
| 为让检查变绿去放宽断言、延长超时、加重试 | 否 | 否 | 否 | 否 | 否 |
| 删去合同未写明要删的可见项或可编辑项 | 否 | 否 | 否 | 否 | 否 |

1. 合同判据要做本表为「否」的动作时：不做，交回「与任务书的偏差」写出判据条号与本表那一行。
2. 本表为「必须」的，合同没写也做。
3. 全量测试、生成、打包由常驻验证做，改到生成链也不例外。**例外**：合同判据要在浏览器或 Mesen 中实测本线生成结果时，只跑产出该结果所需的生成步骤（步骤见项目说明），耗时写进交回；合同判据点名要在 Mesen 中实测编辑效果时，可在编辑器里构建并导出 ROM／SAV 供 Mesen 运行。合同判据点名核对打包产物时，可打包到本地临时目录核对，产物不提交。合同要做的事本身是构建或导出工具时，可运行该工具并与编辑器构建的输出对照，产物不提交。
4. 合同「要做的事」本身要产出的文件（如发布数据引用的证据）不算「检查脚本、探针输出、截图」。
5. 「现成命令」指派活前项目与 shiftboss 里已有的命令，以及 `git`、`node --check` 这类工具自带命令；项目证据目录下的脚本不算。

## 3. 派活方：怎么算做成

| 事项 | 原型 | 成形 | 堆叠 | 收敛 | 维护 |
| --- | --- | --- | --- | --- | --- |
| 界面改动 | 派活方打开页面看到了 | 派活方打开页面看到了 | 派活方打开页面看到了 | 派活方打开页面看到了 | 派活方打开页面看到了 |
| 可见项与可编辑项 | 逐项对照改动前后，有合同未写明的删减即不算做成 | 同左 | 同左 | 同左 | 同左 |
| 其余改动 | 判据点名的现成命令回显对 | 判据点名的检查回显对 | 判据点名的检查回显对 | 判据点名的检查回显对，且常驻验证全绿 | 判据点名的检查回显对，常驻验证全绿，且实测受影响的已发布功能 |
| 合同判据可以要求的动作 | 第 2 节原型列为「必须」的 | 第 2 节成形列为「必须」「是」的 | 第 2 节堆叠列为「必须」「是」的 | 第 2 节收敛列为「必须」「是」的 | 第 2 节维护列为「必须」「是」的 |
| 出现新红 | 挡住在办线才开 `repair`，其余留着 | 挡住在办线才开 `repair`，其余留着 | 挡住在办线才开 `repair`，其余留着 | 每条都开 `repair`，清零才发布 | 每条都开 `repair`，清零才发布 |
| `repair` 线补常驻测试 | 否 | 只为不放松清单 | 只为不放松清单 | 是 | 是 |
| 旧版本的用户数据 | 丢弃 | 丢弃 | 丢弃 | 丢弃 | 保留或迁移 |

## 4. 派活方：选哪一列

| 列 | 什么时候选 | 优先 | 可以牺牲 |
| --- | --- | --- | --- |
| 原型 | 形态未定，先把功能做出来 | 功能点尽快出现 | 结构、测试、已有功能的质量 |
| 成形 | 结构未定或正在迁移 | 结构对齐 | 已有功能的质量暂时退化 |
| 堆叠 | 结构已定，功能待补 | 功能点的数量与可用 | 边角缺陷、性能、打磨 |
| 收敛 | 功能冻结，准备发布 | 正确与稳定 | 新功能 |
| 维护 | 已有发布版 | 不破坏已发布的行为与用户数据 | 开发速度 |
