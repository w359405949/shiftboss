# 完成标准

一件活做到什么程度算完。共五列：原型、成形、堆叠、收敛、维护。

## 1. 查哪一列

1. 列名就是任务书 `meta.json` 里 `完成标准` 的值。
2. 这次改动碰到项目文档（见 `AGENTS.md`）「完成标准」一节的「不放松清单」里的事时，碰到的那部分查「维护」列。
3. 其余全部查 `meta.json` 写的那一列；不看别的列。
4. 用户宣布项目改用哪一列；派活方按项目说明「完成标准」给每份任务书写列名。

## 2. 执行方：段内做什么

开发线只交代码；测试、检查与生成代码归测试与构建线。受保护路径由项目 `shiftboss.toml` 的 `[guard]` 给出，推送守卫拒收越权改动。

| 动作 | 开发线 | 测试与构建线 |
| --- | --- | --- |
| 推送前过 `shiftboss check`（语法、具名导入等合并时的快速检查） | 必须 | 必须 |
| 改了界面：打开页面看改动处 | 必须 | — |
| 开发中临时写脚本查问题，用完不提交 | 是 | 是 |
| 新写检查脚本、探针、常驻测试，提交证据文件 | 否 | 经用户同意（第 7 条）；每项写明守哪条规则、现有检查为何覆盖不到，并列出同时删去的 |
| 跑相关的现有测试 | 否 | 是 |
| 跑全量测试、派生物生成、打包 | 否 | 否 |
| 检查失败后不改任何东西原样再跑 | 否 | 否 |
| 为让检查变绿去放宽断言、延长超时、加重试 | 否 | 否 |
| 删去合同未写明要删的可见项或可编辑项 | 否 | 否 |

1. 本表为「必须」的，合同没写也做；为「否」的，合同写了也不做，交回「与任务书的偏差」写出判据条号与本表那一行。
2. 开发线发现缺测试、检查或生成改动，写进交回，由派活方转交测试与构建线。
3. 派生物生成、全量测试、打包只由常驻验证做。**例外**：合同判据点名在 Mesen 中实测编辑效果时，可在编辑器里构建并导出 ROM／SAV，产物不提交。
4. 测试每条规则只验一个样本：抽查一份真实数据，或一份覆盖全部字段改动的合成样本；不逐条遍历真实数据。
5. 界面只做语法检查与合并前查看；常驻验证只跑不依赖界面、可在命令行直接运行的检查。
6. 常驻测试的范围与深度以项目架构依据中的「验证范围」表为准：表外不加，未登记的模块按表中「默认」行。
7. 新增测试项（测试文件、用例或闸）须先经用户同意，由派活方登记到 `shiftboss.toml` 的 `[verify] approved_tests`；未登记的新增在 `shiftboss check` 与合并时被拒。

## 3. 派活方：怎么算做成

| 事项 | 原型 | 成形 | 堆叠 | 收敛 | 维护 |
| --- | --- | --- | --- | --- | --- |
| 界面改动 | 派活方打开页面看到了 | 派活方打开页面看到了 | 派活方打开页面看到了 | 派活方打开页面看到了 | 派活方打开页面看到了 |
| 可见项与可编辑项 | 逐项对照改动前后，有合同未写明的删减即不算做成 | 同左 | 同左 | 同左 | 同左 |
| 其余改动 | `shiftboss check` 回显通过 | 同左 | 同左 | 同左，且常驻验证全绿 | 同左，常驻验证全绿，且实测受影响的已发布功能 |
| 合同判据可以要求的动作 | 第 2 节该线所在列为「必须」「是」的 | 同左 | 同左 | 同左 | 同左 |
| 出现新红 | 挡住在办线才开 `repair`，其余留着 | 挡住在办线才开 `repair`，其余留着 | 挡住在办线才开 `repair`，其余留着 | 每条都开 `repair`，清零才发布 | 每条都开 `repair`，清零才发布 |
| 旧版本的用户数据 | 丢弃 | 丢弃 | 丢弃 | 丢弃 | 保留或迁移 |

## 4. 派活方：选哪一列

| 列 | 什么时候选 | 优先 | 可以牺牲 |
| --- | --- | --- | --- |
| 原型 | 形态未定，先把功能做出来 | 功能点尽快出现 | 结构、测试、已有功能的质量 |
| 成形 | 结构未定或正在迁移 | 结构对齐 | 已有功能的质量暂时退化 |
| 堆叠 | 结构已定，功能待补 | 功能点的数量与可用 | 边角缺陷、性能、打磨 |
| 收敛 | 功能冻结，准备发布 | 正确与稳定 | 新功能 |
| 维护 | 已有发布版 | 不破坏已发布的行为与用户数据 | 开发速度 |
