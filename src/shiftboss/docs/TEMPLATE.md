# 任务书格式

## 1. 子类型

| 子类型 | 适用 |
| --- | --- |
| `task` 任务 | 有可达完成状态的一件事 |
| `repair` 修复 | 修好一个具体的坏现象 |
| `sweep` 核对 | 低频的全量核对：跑耗时、全量或要精确定位的检查，出清单与归类，不修 |
| `perf` 性能 | 测量并压低一处耗时，输出与改前逐字节相同；可在自己副本跑生成（[DONE.md](DONE.md) 第 2 节第 3 条） |
| `onboard` 上手核对 | 新接入的执行方读执行方规则并答题，只写交回 |
| `triage` 巡检分诊 | 按失败归属汇总常驻巡检某一遍的红页，对照在办线，出报告，不修 |

1. 用 `shiftboss taskbook new --kind <子类型>` 建立，骨架取自 [`templates/<kind>/`](templates/)。
2. 表头与合同骨架已按子类型填写，不得改成其他组合。
3. 新增子类型即在 `templates/` 下新增目录（`meta.json` 与 `contract.md`）。
4. 布局与写权见 [README](README.md) 1.1。

开发线的判据只写要成立什么，以及 [DONE.md](DONE.md) 第 2 节开发线允许的检查；不写探针、新测试、Mesen 等验证动作。

## 2. `meta.json`

只经 `dispatch`、`merge`、`taskbook` 修改。

| 键 | 含义 |
| --- | --- |
| `调度状态` | 派活方写，见状态词表；与交回顶部执行方写的执行状态对称（README 2.4）。存量键 `状态` 由工具读作 `调度状态` |
| `阻塞于` | 等待项；无则 `—` |
| `编写时间` | 建立日期 |
| `子类型` | `templates/` 下的目录名 |
| `交付模式` | 由骨架填写，一律 `自走` |
| `分支` | `codex/<名字>` |
| `你的工作副本` | 本轮副本的绝对路径，由脚本填写；派活方只给副本名或留空由 `dispatch` 分配；一份任务书独占一个 |
| `轮次` | 已派出的最新轮次，由 `dispatch` 维护 |
| `完成标准` | 派出的任务书必填，`原型`／`成形`／`堆叠`／`收敛`／`维护` 之一，按项目说明「完成标准」选；缺或不合法 `dispatch` 拒派。执行方按它查 [DONE.md](DONE.md) 定段内能做什么，`派活方自办` 的没有执行方，不填 |
| `类别` | `架构`／`开发`／`修复`／`核对`／`性能` 之一，决定优先次序与派发、合并条件（README 3.2 第 9 条）；`repair` 骨架默认 `修复`、`sweep` 默认 `核对`、`perf` 默认 `性能`，未填按 `开发` |
| `来源` | 拆分出本任务书的原任务书；非拆分所得不填 |
| `引用任务书` | 引作参考的任务书 |
| `关联在办线` | 与本任务同改文件或有边界的在办线，逗号分隔；执行方可只读查询其会话（README 4.3 第 8 条）；无则不填 |
| `允许改动的范围` / `明确不许碰` | 提示 / 硬约束 |

| 调度状态 | 含义 | 持笔 | 可否派发 |
| --- | --- | --- | --- |
| `编写中` | 未写完 | 派活方 | 否 |
| `待派` | 在办，可派；会话在不在跑看收件箱 | 派活方 | 是，见「阻塞于」 |
| `待定夺` | 等用户决定 | 用户 | 其余条目照常 |
| `派活方自办` | 不派出，派活方自己做 | 派活方 | 否 |
| `已归档` / `已作废` | 已移入 `archive/` | — | — |

词表以外的状态词不认：`dispatch` 只拦 `编写中`、`核对中`、`待议`、`待定夺`、`已归档`、`已作废`，自造的词一律放行。

## 3. `contract.md`（派活方）

1. 只规定要成立什么与判据，不写做法。
2. 用户原话原样引用，转述在后。
3. 每条写「要求」「判据」，其下一行 `- 状态：☐ 未做 ☐ 完成 ☐ 待议`，由执行方勾选。
4. 判据须能区分做成与没做成；基线数字由执行方现测。
5. 判据只要求 [DONE.md](DONE.md) 第 3 节「合同判据可以要求的动作」一行中该任务书那一列允许的动作。
6. 不贴源码（`dispatch` 拒收）；字节表、地址、数据形状照写。
7. 不复述工作流文档与项目说明已有的通用约束与交付条件（不放松清单、完成标准、实测例外、证据目录、生成链回显等），只写本任务特有的；与在办线的分工写进表头「关联在办线」，正文只写写权归属。
8. 引用其他任务书只写名字，不写路径；在办或已归档由读取方按名字找到。
9. 写完或改动任何一句后，整份合同对照表头完成标准在 DONE 的那一列、项目说明与架构依据重查，不自相矛盾；从其他任务书复制的判据逐条删去不适用的。
10. 现成件只列已核对存在的文件或接口，先全仓查出全部消费处；涉及已有组件写「复用」并给路径，不复述其版式；尚未实现的接口写成本线要做的事，「明确不许」不禁止补它。
11. 收窄、移除类要求写明须保留的既有能力，判据含改前改后对照。
12. 改共用组件或共用样式的，判据含改前改后逐页版面对照；有状态切换的交互页，判据写全部状态逐一巡检。
13. 改共用入口或共用实现、删除或迁移发布副本、改绑数据来源的，列出全部使用方（浏览器与生成端）与使用方式（克隆、序列化等），判据要求逐个使用方的回显。
14. 判据只引用仓库内或本线可重新生成的东西；要沿用他线证据，在那条线 `--done` 前存进任务书。
15. 性能判据用同负载下改前改后的交替对照，不要求独占机器；耗时分冷启动（空浏览器配置）与已缓存（同一配置填满缓存后）两种状态测，绝对值只作同条件对照。
16. 开发线与修复线的判据只写源码层面与快速检查能证明的事；页面、生成、构建与全量结果由常驻验证给出，不写进判据（性能线见 `perf` 行）。

## 4. `rounds.md`（派活方）

1. 只经 `dispatch -m`／`-F` 追加；末条为本轮交代。
2. 只写本轮独有信息。

## 5. `delivery.md`（执行方）

每轮重写。标题下一行写执行状态 `执行状态：进展`／`执行状态：完成`／`执行状态：停下`（README 2.4），其后五段：逐条状态；做成了什么（实测数字、地址、哈希）；被什么挡住；与任务书的偏差；文档冲突（与项目架构依据冲突的文档路径与冲突处，无则写「无」）。
